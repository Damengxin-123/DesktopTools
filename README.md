# DesktopTool 桌面工具

使用 **Qt 原生窗口 + HTML/CSS/JavaScript + QWebChannel + Qt 业务服务** 的 Windows 桌面工具。页面通过 Qt 资源系统随程序打包，离线运行，不需要 Node.js、npm 或本地 HTTP 服务。

## 功能与架构

- **快捷方式**：目录、网址、文件的分类管理、搜索、编辑、批量删除与排序，由 Qt 调用系统打开目标。
- **便签**：分类管理、富文本编辑与图片保存；Qt 负责内容过滤、文件访问及数据保存。
- **网页书签**：在独立窗口中管理常用网址。左侧书签列表支持搜索、新增、编辑、删除、批量删除与拖动排序，点击列表项即在右侧真实浏览区打开该网址，可正常登录、上传和下载文件（下载保存到设置中的默认下载目录），工具栏提供后退、前进、重新加载、停止、地址栏与“系统浏览器打开”。新增或修改时输入网址会自动检测：能打开就把网页标题填入名称框，打不开则提示原因并保留手动输入；也可一键收藏右侧当前网页。
- **表情**：对本地表情图像文件做分类管理和关键字检索；添加时设置检索关键字，也可把当前剪贴板中的图像或复制的单个文件直接添加为表情，支持打开原文件所在位置（资源管理器中选中文件）和把原文件复制到剪贴板，复制不进入剪贴板历史。
- **剪贴板**：勾选文本、图像、文件 / 文件夹、链接或其他格式信息后自动保存复制历史；支持完整文本搜索、类型筛选、详情、再次复制、置顶、批量删除及清空。
- **下载**：支持 HTTP/HTTPS 和磁力链接，查看进度、速度和历史记录；磁力任务获取文件清单后，由用户勾选并确认才下载内容，支持暂停、继续、取消及打开所在目录。
- **动态壁纸**：把本地 GIF、动态 WebP 等动图或 MP4、WebM 等视频设为桌面壁纸；壁纸窗口通过 Windows WorkerW 接口挂载到桌面图标层之下，不影响图标和正常操作。支持开关、从本地或剪贴板选择资源、历史记录管理，源文件丢失时弹窗提示。
- **网格图**：用于绘制简单区域示意图的栅格画板；画布中心为坐标原点 (0,0)，可向四周无限延伸。选择颜色后点击格子涂色，网格线与从中心向四个方向延伸的坐标轴清晰显示，坐标轴比普通网格线更粗。支持常用颜色、调色盘、橡皮擦、Alt+点击吸色、可调画笔半径，滚轮缩放、右键拖动画布、按住空格框选填色、Ctrl+Z 撤销涂色；可设置网格线颜色和粗细（随项目保存）。项目列表支持新建、重命名、删除，双击进入编辑；保存时只记录被涂色格子的坐标和颜色数值，可导出或一键复制为 PNG。
- **二维码识别**：打开本地图片或粘贴剪贴板中的二维码图片，加载后点击“识别”把内容放入只读文本框，可一键复制；左侧历史记录显示二维码缩略图与识别内容，点击回看，支持单条删除与清空。识别由内置解码器离线完成，支持旋转、反色、适度缩放与轻微透视，无需联网。
- **截图**：通过全局热键（默认 Ctrl+Alt+A，可在截图页自定义）或页面按钮发起全屏截图遮罩，拖拽框选区域后进行标注——画笔、直线、矩形、椭圆、箭头和文字，配六种颜色与三档粗细（同时决定文字字号），支持逐步撤销。选区出现后默认进入“移动”工具：框内拖动整体平移选区，边框四角与四边中点的 8 个手柄微调大小，在框外拖动则重新框选新区域，右键或 Esc 取消整次截图。确认后截图自动写入系统剪贴板，并在截图页保留记录：缩略图列表显示截图时间（精确到秒）、尺寸与文件大小，点击缩略图查看原图，可复制、打开位置或删除。页面顶部的开关可整体停用截图功能（解除热键并禁用开始按钮），重新开启后恢复。
- **设置**：界面语言、字号、全局热键、默认下载目录、开机自启和恢复默认设置。在“设置 → 界面 → 界面语言”选择“简体中文”或“English”，立即切换并自动保存，无需重启。仅翻译程序界面文案；用户的文件名、路径、便签、分类、书签标题及输入内容保持原样，未保存的编辑内容不会因切换语言而刷新。勾选“开机自启”并保存后，在当前用户登录 Windows 时启动；取消勾选并保存或恢复默认设置会移除自启项。自启使用当前程序路径与数据目录，无需管理员权限。热键注册、自启项修改及设置写入一起成功后生效。设置页底部的“关于”卡片展示作者 GitHub 头像、昵称和项目仓库地址，点击跳转按钮会在系统浏览器中打开仓库。
- **系统集成**：托盘、默认 F8 唤醒、单实例唤醒及兼容旧版本的实例标识。有托盘时关闭窗口会隐藏，真正退出使用托盘菜单。

应用包含快捷方式、便签、网页书签、表情、剪贴板、下载、动态壁纸、网格图、二维码、截图、设置等页面（网页书签在独立窗口中打开）。旧版的登录和日志占位页面未纳入新版。

```text
HTML 页面 → web/bridge.js → QWebChannel → AppBridge → Qt 业务服务 → 数据文件
                                             └→ 文件选择、剪贴板、系统热键
```

| 目录 | 用途 |
| --- | --- |
| `src/app/` | 原生窗口、WebEngine 安全边界、托盘、全局热键和动态壁纸挂载 |
| `src/bridge/` | 唯一网页接口 `AppBridge`，协调系统操作和服务调用 |
| `src/services/` | 快捷方式、便签、网页书签、表情、剪贴板、下载任务、动态壁纸、网格图、二维码识别、截图历史和设置服务，校验数据并持久化 |
| `web/` | HTML、CSS、JavaScript 页面与异步桥接封装 |
| `resources/` | 应用图标、Windows 资源及将网页编译进应用的 Qt 资源清单 |
| `tests/` | 服务回归测试和真实 WebEngine / WebChannel 集成测试 |
| `pack/` | 本机更新、生成不含用户数据的便携 ZIP 压缩包 |

仓库以新版 `src/` 和 `web/` 为活动代码，不再包含旧版 `code/`、编译缓存或预先打包的 Qt 运行库。旧版源码可从 Git 历史查看；用户数据格式的兼容与迁移继续由新版服务提供。

页面只负责展示和交互；数据校验、读写、打开文件及系统集成由 Qt 处理。便签 HTML 经后端重建，资源请求和页面导航受限，外部网页不会加载到承载原生接口的页面中。

## Windows 图形兼容

Windows 默认优先使用 Microsoft WARP 软件图形设备，Qt Quick 与 Chromium 共用该设备，避免网页合成在显卡驱动中长期等待，导致主界面、托盘和退出一起失去响应。软件设备模式下放行 WARP 的 WebGL2，保留地形编辑；复杂三维场景的 CPU 占用可能高于硬件渲染。原生视频解码仍沿用 Qt Multimedia 的设备策略。

配置在创建 Qt 应用前生效，不修改系统或用户级环境变量。需要比较硬件性能时，可仅在启动该程序的 PowerShell 会话设置 `$env:QSG_RHI_PREFER_SOFTWARE_RENDERER='0'` 后运行程序；删除该会话变量即可恢复默认兼容模式。用户已经指定的 Qt 渲染后端、适配器和 Chromium 参数会保留。

2026-10-15 的卡死现场与恢复诊断保存在本机 `out/diagnostics/20261015-hang/`；转储显示主线程在 `Qt6WebEngineCore → d3d11 → nvwgf2umx` 路径等待。该目录包含本机进程信息和转储，不随发行包分发。
## 剪贴板历史

在“剪贴板”页顶部勾选需要保存的内容类型，勾选立即保存并在下次启动恢复；首次使用默认不记录，全部取消勾选即暂停。程序运行期间监听系统剪贴板变化，包括其他程序中的复制和剪切，隐藏到托盘后仍然有效；退出程序期间的复制无法补录，启动时也不会把已有剪贴板内容当作新事件。

聊天软件一次复制可能多次更新剪贴板格式。连续 1 秒内实际保存内容相同的通知只记一次，补充 HTML 格式或改变文本换行形式不会重复新增；原文保持不变。窗口从首次成功记录起计算，重复通知不会延长。不同内容立即保存，超过窗口再次复制相同内容也会新增；只记录格式名称的“其他”类型不作内容去重。

卡片显示内容类型和本地复制时间（精确到秒）。文本按纯文本保存，图片保存 PNG 内容并显示缩略图；普通文件和文件夹只保存名称、路径，不备份文件实体。复制的图像文件、截图，以及聊天工具提供的图像内容或可读取的本地图像缓存均归入“图像”；同时提供单张图像和临时路径时优先保存图像。按文件内容识别图像，兼容没有常见图片扩展名的缓存；读取前检查尺寸。一次复制多张图片或混合图片与普通文件时，分别按图像实体和文件引用保存，各自遵循类型勾选。无法解码或超出限制的图片会显示提示，不改归普通文件。带 URL 数据的其他复制归入“链接”，普通网址文本归入“文本”。其他应用专有格式仅保留格式名称，不保存二进制内容，不能恢复原内容；没有本地路径的虚拟文件也不会自动下载或实体化。

可搜索完整文本和文件路径，按类型筛选、查看详情、再次复制、置顶、全选当前结果、批量删除或确认清空。全选包含当前筛选结果的所有分页；清空包含置顶记录。再次复制文件会恢复系统文件引用供粘贴使用；原路径失效时会显示错误，历史中的名称和路径仍可查看或复制。删除历史不会删除引用的原文件。

历史和监听设置保存在数据目录的 `clipboard-history.v1.json`。最多保留 500 条、64 MB，达到上限自动移除最早的未置顶记录；置顶内容占满容量时会提示并跳过本次复制。单条文本 / 路径信息上限 2 MB，图片上限 2000 万像素且 PNG 不超过 8 MB，单次文件 / 链接上限 1000 项。索引损坏或保存失败会显示提示，不覆盖原数据。

## 表情管理

在“表情”页集中管理自己的表情图片文件。点击“添加表情”从原生对话框选择图片（支持 Qt 可读取的全部图像格式），或点击“从剪贴板添加”使用当前剪贴板内容——复制的单个文件直接引用原位置，截屏等纯图像内容会先保存到数据目录的 `emoji/clipboard` 子目录；随后在对话框中设置检索关键字和所属分类。表情记录仅引用文件，不会移动文件实体。列表显示缩略图、文件名、原路径和关键字，关键字与文件名都参与搜索，不区分大小写。

表情按分类组织：分类可新建、重命名和删除，删除分类会把其中的表情移回默认分类。卡片提供复制文件、打开位置、编辑和删除操作：

- **复制文件**：把原文件写入系统剪贴板供粘贴，同时提供文件引用和图像内容——文件管理器粘贴的是文件，聊天工具可直接粘贴图片。该复制通过剪贴板服务的还原标记屏蔽，不会记录进剪贴板历史；其他应用发起的复制仍正常记录。
- **打开位置**：用资源管理器打开原文件所在目录并选中该文件；原文件被移动或删除后显示中文错误，记录中的缩略图和路径仍可查看。
- **删除**：只移除表情记录，不删除原文件；批量确认与分类迁移不改动磁盘内容。

表情库和分类保存在数据目录的 `emoji/emoji-library.v1.json`，最多 2000 条、128 MB，缩略图随索引保存。添加时校验图片可读且不超过 2000 万像素，同一分类内不允许重复添加同一文件。索引损坏或保存失败会提示并停止写入，不覆盖原文件。

## 动态壁纸

在“壁纸”页把本地动图或视频设为桌面壁纸。开启顶部的“开启动态壁纸”后，点击“选择本地资源”从原生对话框挑选 GIF、动态 WebP 等动图或 MP4、WebM、MKV 等视频，或点击“从剪贴板添加”使用当前剪贴板内容——复制的单个文件直接引用原位置，截屏等纯图像内容会先保存到数据目录的 `wallpaper/clipboard` 子目录；立即显示为桌面壁纸。未开启时选择资源只保存到历史记录。壁纸通过 Windows WorkerW 接口显示在桌面图标层之下：图标、右键菜单和桌面操作不受影响，程序隐藏到托盘后壁纸继续显示，退出程序后壁纸停止，下次启动开启状态会自动恢复上次的资源。

历史记录以卡片列表管理，最多 100 条，显示预览缩略图（视频显示占位图标）、文件名、原路径、类型和添加/使用时间：

- **使用**：切换到这条记录；当前资源被移动或删除时弹出“资源已丢失”对话框说明原因和原路径，可以恢复文件后重试或删除记录。
- **打开位置**：用资源管理器打开原文件所在目录并选中该文件。
- **删除**：只移除历史记录，不删除原文件；删除当前使用的记录会停止壁纸显示，开关保持原样。

壁纸页自动检测已连接显示器，按实际位置和分辨率绘制屏幕示意图。点击屏幕编号，再添加资源或点击历史卡片的“应用到此屏”，只改变选中屏幕的壁纸；“此屏恢复系统壁纸”仅撤回该屏窗口。每块屏幕独立覆盖完整显示区域，媒体等比裁切填满；支持不同缩放率、负坐标、竖屏及屏幕热插拔。未配置的屏幕保留系统壁纸，断开屏幕的设置保留，重新连接后恢复。关闭总开关或退出程序时立即撤回全部壁纸窗口。

显示器示意图下方可勾选图片显示方式，每屏独立保存：填充（等比裁切铺满）、适应（完整显示并留黑边）、拉伸（铺满并允许变形）、平铺（按原图像素从左上角重复）、居中（原图像素居中，超出裁切）。示意图使用静态缩略图显示对应效果，动图预览不播放；关闭总开关时仍可预览和保存方式。桌面图片与示意图共用布局规则，原图像素尺寸用于计算平铺和居中的真实比例。视频仍按填充播放，选择视频时图片方式控件禁用。

同一文件不会重复记录，重复添加等同应用到当前选中屏幕。历史、开关和每屏选择保存在数据目录的 `wallpaper/wallpaper-history.v1.json`，文件名保持兼容，内部格式已升级为版本 2；旧版的统一壁纸会迁移为各连接屏幕的独立选择。静图缩略图随索引保存。索引损坏或保存失败会提示并停止写入，不覆盖原数据；资源管理器重建桌面后，程序会在数秒内自动重新挂载壁纸窗口。找不到安全的图标下方宿主时提示失败，不回退到可能遮挡桌面操作的窗口层。

## 网格图

“网格图”页用于绘制简单区域示意图。左侧是网格图项目列表，支持新建、重命名和删除，**双击项目进入编辑**；右侧画板以画布中心为坐标原点 (0,0)，网格向四周无限延伸，只保存被涂色格子的坐标和颜色数值，适合表示房间、区域等相对位置而不是精确尺寸。

编辑操作：

- **涂色**：在“常用颜色”中选择色块，或用“调色盘”自定义颜色后，左键点击或拖过格子涂色；快速拖动经过的格子由直线插值补全。“橡皮擦”把点击改为清除格子颜色。工具栏“半径”调整画笔大小：涂色覆盖以点击格子为圆心、半径 N 格的圆形区域（0 为单格、1 为 3×3、2 为去角的 5×5，以此类推），拖动时圆形笔触沿路径落下，橡皮擦同样生效。
- **视图**：滚轮以光标为锚缩放（每格 6–96 px），按住右键拖动画布，“复位视图”回到原点居中；状态栏实时显示悬停格坐标、缩放比例和格子数。
- **框选**：按住空格键后左键拖出矩形，预览覆盖范围内的格子，松开鼠标时整片设置为当前颜色；橡皮擦开启时整片清除。整个框选记为一步，Ctrl+Z 一次全部撤销。
- **吸色**：按住 Alt 并左键点击格子，把该格子的颜色吸取为当前颜色；空白格子不改变当前选择。当前使用的颜色固定显示在常用颜色区最左侧，点击它可从橡皮擦恢复涂色。
- **撤销**：Ctrl+Z 或工具栏“撤销”按笔画回退涂色，最多保留 200 步。
- **网格线**：网格线颜色和粗细（1–6 px）可自由设置并随项目一起保存；从中心向四个方向延伸的坐标轴始终比普通网格线更粗。
- **保存**：点击“保存”或 Ctrl+S 写入数据；有未保存修改时切换页面或项目会先确认。
- **导出**：把当前内容（含网格线和坐标轴，范围取涂色格子的包围盒加一圈余量）渲染为 PNG，“导出 PNG”保存到选择的位置，“复制 PNG”直接写入系统剪贴板供粘贴。

项目索引和栅格数据保存在数据目录的 `gridmap/index.v1.json` 与 `gridmap/maps/<项目ID>.json`，坐标以画布中心为原点、范围为 ±1000000，单个项目最多 200000 个格子。索引损坏或保存失败会提示并停止写入，不覆盖原数据。

## 二维码识别

“二维码识别”页把二维码图片变成文本：点击“打开本地图片”从原生对话框选择图片，或复制图片后点击“从剪贴板粘贴”，图片会显示在预览区；确认内容无误后点击“识别”，解码出的文本放入下方只读文本框，旁边“复制”按钮可一键写入系统剪贴板。“清除图片”可回到空状态重新开始。

识别在本地离线完成：程序内置自研解码器，处理灰度二值化、定位图案检测、透视网格重建、掩码还原、纠错块去交错与数据段解码，支持全部 40 个版本、四种纠错级别和数字 / 字母数字 / 字节（UTF-8，失败时尝试 GB18030）/ ECI 数据段，可应对任意旋转、反色、适度缩放和轻微透视变形的截图与照片。不还原纠错码字，图片损坏过多时会给出中文原因而不是错误内容。

左侧“识别历史”显示二维码缩略图、内容预览、来源和日期，点击回看原图与完整内容，可逐条删除；重复识别相同内容只保留最新一条。历史保存在数据目录的 `qr-history.v1.json`，最多 100 条、64 MB，单张图片 PNG 不超过 8 MB（超限时自动缩小后保存），超限自动移除最早的记录；索引损坏或保存失败会提示并停止写入，不覆盖原数据。

## 截图

在“截图”页点击“开始截图”或按下截图热键（默认 Ctrl+Alt+A，页面顶部可修改并立即生效；程序隐藏到托盘时同样可用；顶部开关关闭后热键解除、按钮停用）进入全屏截图遮罩：整屏变暗后拖拽框选区域，选区内恢复原始亮度并显示尺寸标签，底部工具栏提供标注与操作按钮。

选区交互与标注工具：

- **移动与缩放**：选区出现后默认是“移动”工具——按住选区内拖动整体平移截图框（大小不变），边框四角与四边中点显示 8 个白色手柄，拖动手柄向对应方向微调大小；在选区外按下并拖动表示放弃当前选区、重新框选新区域，过小的拖拽视为误触并恢复原选区。
- **形状与笔画**：切换到文字、画笔、直线、矩形、椭圆或箭头后在选区内操作。文字工具点击选区放置行内输入框，输入后 Enter 提交、Esc 丢弃；六种颜色、三档粗细（粗细同时决定文字字号），“撤销”逐步回退标注。
- **结果**：Enter 或“完成”结束截图，图像自动写入系统剪贴板并保存到页面下方的截图记录；右键或 Esc 随时取消整次截图，不会产生记录。

截图记录以缩略图列表展示，包含截图时间（精确到秒）、像素尺寸和文件大小；点击缩略图查看原图，每条记录可重新复制、打开文件所在目录或删除，“清空记录”删除全部历史与文件。截图 PNG 保存在数据目录的 `screenshots/` 子目录，索引为 `screenshots/index.v1.json`，最多 100 张，达到上限自动移除最早的记录及文件；索引损坏或保存失败会提示并停止写入，不覆盖原数据。

多显示器环境会为每块屏幕分别显示遮罩，选区限制在其中一块屏幕内；每块屏幕按自身的缩放比例（DPI）精确抓取与裁剪，4K / 150%、200% 缩放下按物理像素保存，不会模糊或错位，选区不跨屏。

## 下载任务

在下载页填写 HTTP/HTTPS 文件网址即可创建任务，也可为单次下载选择目录。设置中的默认下载目录初始为系统“下载”文件夹，清空后保存可恢复系统默认位置；自定义默认目录须已存在且可写。

输入 `magnet:?` 链接时自动进入磁力流程：先解析链接并连接节点获取文件清单，随后弹出文件选择窗口，支持全选、全不选及查看选中大小。至少勾选一个文件后点击“开始下载”，才传输文件内容。关闭弹窗会保留“等待选择文件”的任务，可从卡片重新打开；暂停、重启或重试不会跳过确认步骤。

磁力任务由本机 libtorrent 引擎处理，不使用第三方解析网站。每个任务保存到独立目录，避免覆盖已有文件；完成所选文件后停止传输。获取清单和下载速度取决于可用节点，暂时没有节点时可暂停后再继续。

不带 tracker 的磁力链接通过多个 DHT 引导入口寻找来源，单个入口的 DNS 或连接异常不会成为唯一阻塞点。节点网络建立后会补发文件来源查询；解析卡片显示等待时间，并区分正在连接资源网络、寻找来源和获取文件信息。网盘可能已缓存文件清单，本机解析仍需要能通信的在线来源。

任务可暂停后继续；服务器支持可靠的断点续传时，会接着已有内容下载，不支持时重新下载。任务所选目录不可用时，会回退到默认目录，并在任务中显示说明；默认目录也不可用时，依次尝试系统“下载”目录和应用数据目录中的 `downloads` 文件夹。

HTTP/HTTPS 连接连续 30 秒没有数据或暂时中断时，任务会在 1、2、4 秒后自动重试，单轮最多三次。有可靠断点标识时从已保存的位置继续，否则安全地重新下载；等待重试时仍可暂停或取消。超过次数后会显示失败，点击“重试”可重新开始一轮。

下载历史会保留，应用重启后不会自动发起下载：原下载中的任务变为暂停，暂停或失败的任务可通过“继续”或“重试”恢复。下载完成的文件不会被自动打开或执行，可以使用“打开目录”自行查看；移除完成记录会保留文件。

## 地形编辑

“地形”页面向游戏关卡制作：以米为单位编辑规则高度场，用七种画笔直接塑造山地、河流、道路、湖泊与海岸，并导出 UE 可参考的 16 位灰度高度图。项目列表在页面左侧，右侧是选中项目的**只读三维缩略预览**（可旋转、缩放，不可修改），**双击项目或预览模型打开独立编辑窗口**；重复打开同一项目会激活已打开的窗口，保存后主页预览自动刷新。删除项目需要确认，项目正在编辑窗口中打开时会被拒绝。

新建项目设置名称、宽度、长度、采样间距与初始地面高度；尺寸不能被采样间距整除时按顶点数向下取整并明确显示实际尺寸。编辑窗口为三栏布局：左侧工具栏（细节 / 调整 / 山 / 河流 / 道路 / 湖泊 / 海岸画笔 + 导出 / 设置 / 撤销 / 重做 / 保存），中间三维视图，右侧当前工具参数。状态栏显示未保存状态、实际尺寸、采样间距、网格分辨率与操作提示。

编辑操作：

- **视图**：右键旋转、中键平移、滚轮缩放（左键保留给画笔，与 Alt 不冲突）。
- **细节画笔**：左键抬高，按住 Alt 左键降低；效果按力度（米/秒）与作用时间归一化。
- **调整画笔**：平滑减少高度突变；平整把整个笔划逐渐调整到**落笔时**的高度（拖动中目标不漂移）；锐化增强已有起伏且单次变化限幅。
- **山画笔**：圆润丘陵 / 尖峰山地 / 山脊 / 台地四种预设形状可辨认；山脊方向跟随绘制方向；噪声使用固定种子的空间噪声，绘制时不跳变；重复落笔收敛到包络。
- **河流画笔**：沿路径生成河床与河岸；河深相对**本次笔划开始前**的地面计算，同一笔划反复覆盖不会越挖越深，新笔划可基于当前地形继续挖深；地层类型（松软 / 普通 / 坚硬）控制岸坡宽度与坡度。
- **道路画笔**：路面横向保持水平，纵向随笔划前的原地形并做平滑；平缓 / 陡直路基控制边坡宽度；不生成垂直面与悬空结构。
- **湖泊画笔**：拖动形成连续湖盆与岸坡，盆底柔和，深度规则与河流相同。
- **海岸画笔**：以设定海平面为参考重塑岸坡（沙质缓岸 / 土质斜岸 / 岩质陡岸），保留岸线两侧高低关系；范围内缺少岸线过渡时不修改并提示；半透明海平面仅为预览，不写入数据，勾选“显示海平面”后即使切换到其他画笔也持续显示。
- **撤销与重做**：一次完整笔划为一个事务，按脏矩形保存前后高度；Ctrl+Z / Ctrl+Y，默认 30 步（1–200 可设置并显示内存占用），无实际变化的操作不占步数；鼠标移出、窗口失焦会正确结束笔划。
- **设置**：调整编辑采样间距会执行重采样（显示新网格、实际尺寸与内存估算，明确提示撤销历史将被清空）；重采样只影响内存数据，保存后才落盘。
- **导出**：真正的 16 位单通道灰度 PNG（黑色最低、白色最高、线性映射，平坦地形映射中点灰），导出间距 ≥ 编辑间距、不能整除时明确提示实际间距；同时输出同名 JSON 说明文件，记录分辨率、映射范围、行列为方向、格式版本、独立回读校验结果与 UE Landscape 合法分辨率建议。导出不改变工程数据。

画笔大小以世界空间米为单位（快捷键 `[`、`]`），快速拖动时笔划按路径插值连续不间断。所有画笔直接修改同一份浮点高度数据，不留可编辑轨迹对象。

项目数据保存在数据目录 `terrain/index.v1.json` 与 `terrain/projects/<项目ID>/`（`project.json` 元数据、`heightmap.bin` 浮点高度 + 文件头、`thumbnail.png` 仅作展示缓存），写入使用临时文件安全替换；高度数据在读取与保存时都做完整性校验（尺寸一致、无 NaN、范围受限），索引损坏时禁止覆盖。

## 构建与运行

需要 Windows x64、MSVC x64 C++ 工具链、CMake 3.21 或更新版本、Ninja，以及 **Qt 6.8 或更新版本的 MSVC x64 套件**。Qt 组件需包含 `Core`、`Gui`、`Widgets`、`Network`、`WebChannel`、`WebEngineWidgets`、`Multimedia`、`MultimediaWidgets`；默认启用测试，还需 `Test`。项目使用 C++17；磁力下载依赖 libtorrent 2.1，仓库的 `vcpkg.json` 固定依赖基线并关闭不需要的 WebTorrent 功能。

视频壁纸使用 Qt Multimedia 的独立播放器静音循环播放，等比例裁剪填满各自屏幕，不依赖 WebEngine 是否启用 H.264。解码失败会撤回该屏壁纸窗口并显示原因，其他屏幕继续播放；再次选择资源或重新开启可重试。图片和 GIF 继续使用网页显示。发布时须执行完整 CMake 安装流程，让 Qt 官方部署工具一并复制 Multimedia 插件及 FFmpeg 运行库，不能只替换 EXE。

地形编辑页面前端由 `frontend/` 下的 TypeScript + Vite 构建，产物提交在 `web/dist/`，常规 C++ 构建无需 Node.js。修改前端后执行：

```bat
cd frontend
npm ci
npm run build   (输出到 web\dist，随 app.qrc 打包)
npm test        (vitest 单元测试：画笔、撤销、重采样、导出映射)
```

先打开 Visual Studio 的 **x64 Native Tools Command Prompt（x64 原生工具命令提示符）**，进入克隆的仓库根目录。CMake 和 Ninja 需位于 `PATH`。以下使用已验证的 Qt 6.10.3 举例，请将 Qt 路径替换为自己的安装位置：

```bat
set "QT_ROOT=C:\Qt\6.10.3\msvc2022_64"
set "VCPKG_ROOT=C:\dev\vcpkg"
set "PATH=%QT_ROOT%\bin;%PATH%"
cmake --preset x64-release -DCMAKE_PREFIX_PATH="%QT_ROOT%" -DCMAKE_TOOLCHAIN_FILE="%VCPKG_ROOT%\scripts\buildsystems\vcpkg.cmake" -DVCPKG_TARGET_TRIPLET=x64-windows-static-md
cmake --build --preset x64-release
ctest --preset x64-release
```

开发者命令提示符负责初始化 MSVC x64 编译器环境，也可手动调用 Visual Studio 安装目录下的 `Common7\Tools\VsDevCmd.bat -arch=x64 -host_arch=x64`。Qt 的 `bin` 加入 `PATH` 供开发运行及测试加载 DLL。若 Ninja 未加入 `PATH`，把其安装目录一并加入，或在配置命令中指定 `-DCMAKE_MAKE_PROGRAM=完整路径`。

项目不固定开发者机器上的 Qt 安装路径。使用 `-DCMAKE_PREFIX_PATH` 指定完整套件，或将个人配置写入已忽略的 `CMakeUserPresets.json`。

`VCPKG_ROOT` 指向已执行 `bootstrap-vcpkg.bat` 的官方 vcpkg 仓库。首次配置会构建磁力依赖；`x64-windows-static-md` 将 libtorrent 及依赖静态链接，同时使用与 Qt 一致的动态 MSVC 运行库。已有独立依赖安装也可通过 `CMAKE_PREFIX_PATH` 提供 `LibtorrentRasterbarConfig.cmake`。从旧构建切换到 vcpkg 工具链时使用新的构建目录，或在 CMake 3.24 及以上添加 `--fresh` 重新配置。

独立依赖还验证过 libtorrent 2.1.2、Boost 1.85 头文件与 OpenSSL 3.6.3 的组合。使用动态 OpenSSL 时，通过 `OPENSSL_ROOT_DIR` 指定同一版本的头文件和库，并将两个 DLL 的完整路径以分号分隔传入 `DESKTOPTOOL_EXTRA_RUNTIME_FILES`；安装流程会将它们放在程序旁。开发运行和测试时也需将其 `bin` 目录加入 `PATH`。标准 vcpkg 静态配置不需要额外 DLL。

调试版本将三个命令的 preset 改为 `x64-debug`。输出分别为：

- 发布构建：`out/build/web-x64-release/bin/DesktopTool.exe`
- 调试构建：`out/build/web-x64-debug/bin/DesktopTool.exe`

切换 Qt 套件时需清理旧配置缓存，例如 CMake 3.24 及以上可执行 `cmake --fresh --preset x64-release -DCMAKE_PREFIX_PATH="完整Qt套件路径"`，随后重新构建。头文件、导入库和运行时 DLL 必须来自同一完整套件。

从开发构建启动时，默认数据目录也在该可执行文件旁。要使用原来的数据，请指定其路径：

```bat
out\build\web-x64-release\bin\DesktopTool.exe --data-dir "D:\DesktopTool\data"
```

- `web-integration`：在真实 WebEngine 和 WebChannel 中验证页面与 Qt 后端调用，以及下载表单、路径回退、多任务卡片、暂停/继续/取消、磁力文件勾选弹窗、逐字节文件比对、表情卡片、关键字搜索、分类筛选与复制文件操作，网格图的新建、双击编辑、涂色、空格框选、橡皮擦、撤销、缩放、画布拖动、线条设置保存和项目删除，二维码页的剪贴板粘贴、识别、复制结果与历史管理，以及截图页的历史列表、复制、预览、删除与热键保存；测试关闭托盘和全局热键，使用离屏模式及本机 HTTP/BitTorrent 服务。

测试结果以当前构建运行时的 CTest 输出为准。真实系统的托盘、热键占用和最终发布目录运行仍需在目标 Windows 环境检查。`web-integration` 同时验证壁纸屏幕选择、按屏应用和恢复系统壁纸的页面桥接。`wallpaper-smoke` 是手动运行的冒烟程序（不进入 ctest），使用临时数据在所有连接屏幕循环开关三次，检查媒体加载、完整物理矩形、网页内容铺满、窗口禁用输入以及关闭后原生句柄立即销毁；桌面壁纸区域会短暂显示验证图案后恢复，不发送鼠标操作。

二维码测试图 `tests/media/qr-*.png` 随仓库提供，由 `tests/tools/make-qr-fixtures.py` 离线生成：脚本内置一个最小 QR 编码器（依赖 Python 3 与 Pillow，不联网），在写入前自校验总码字、余位与数据容量，覆盖版本 1–7、四种纠错级别、数字 / 字母数字 / 字节 / ECI 段、多块交错及旋转、缩放、反色变换。修改解码器的采样或几何逻辑后重新运行该脚本即可重建全部 fixture；修改 `src/services/QrDecoder.cpp` 中的 RS 块结构表 `kBlockStructures` 后，必须运行 `tests/tools/verify-rs-table.py`，它校验表中每个条目满足“块数 ×（数据 + 纠错码字）等于算法推导的版本总码字”，任何不一致都会打印出具体条目。

## 本机更新与便携发布

完成发布构建并退出正在运行的应用后执行：

```bat
pack\copy_lib.bat
```

该脚本使用 `cmake --install out/build/web-x64-release --prefix out/bin` 更新原有本机程序目录，保留原来 `out/bin/data`。之后从 `out/bin/DesktopTool.exe` 启动即可继续使用原数据。

生成不含用户数据的便携 ZIP：

```bat
pack\pack_app.bat
```

脚本调用 Windows 自带的 PowerShell 5.1，每次将当前 Release 构建通过 CMake 安装到全新的临时目录，再生成压缩包。默认输出为 `out/packages/DesktopTool-版本号-windows-x64-时间戳.zip`，同时生成同名 `.zip.sha256` 校验文件。

压缩包根目录包含 `DesktopTool-版本号-windows-x64` 程序目录和 `install.bat` 安装程序，两种用法任选：

- **安装模式**：解压后运行 `install.bat`，按提示输入安装位置（例如 `J:\TOOL`），安装程序会在其中创建 `DesktopTool` 子目录并复制全部文件，可选创建桌面快捷方式。升级安装只覆盖程序文件，`data` 用户数据原样保留；卸载运行安装目录内的 `uninstall.bat`。安装程序也支持静默用法：`install.bat J:\TOOL`。
- **便携模式**：直接进入 `DesktopTool-版本号-windows-x64` 文件夹运行 `DesktopTool.exe`。

压缩包包含主程序、Qt 运行库和插件、WebEngine 子进程及资源、语言包、配置和第三方许可证；HTML/CSS/JavaScript 与应用图标已经编译进程序。Qt 部署流程附带 `vc_redist.x64.exe` 时一并保留，目标电脑缺少 MSVC 运行库时可先安装它。使用动态 OpenSSL 的构建仍须配置 `DESKTOPTOOL_EXTRA_RUNTIME_FILES`，确保两个 DLL 随安装部署。

打包不会读取或复制 `out/bin`、`pack/app` 或任意用户下载目录，因此不会带入便签、快捷方式、设置、下载记录、磁力缓存及已下载文件，也不会修改本地用户数据。脚本检查关键发布资源是否齐全，拒绝部署树中的用户数据目录、日志、调试文件和链接；失败返回非零退出码，已有 ZIP 保持不变。正常完成后自动清理本次临时目录。

可以指定构建目录和输出目录，路径含空格时加双引号：

```bat
pack\pack_app.bat -BuildDirectory "D:\DesktopTool\out\build\web-x64-release" -OutputDirectory "D:\Release Packages"
```

也可直接运行 `pack/package_release.ps1`，支持相同参数。打包脚本优先使用 `-CMakePath` 或 `DESKTOPTOOL_CMAKE` 指定的程序，未指定时使用构建缓存记录的 CMake，再回退到 `PATH`。本机更新脚本 `copy_lib.bat` 使用 `DESKTOPTOOL_CMAKE` 或 `PATH`。例如：

```bat
set "DESKTOPTOOL_CMAKE=C:\Program Files\CMake\bin\cmake.exe"
pack\pack_app.bat
```

磁力引擎及其依赖的完整许可证位于 `third_party/licenses`，会随包放入 `licenses` 目录。打包产物位于 Git 已忽略的 `out` 目录，不提交到源代码仓库。

## 扩展页面与接口

1. 在 `src/services/` 实现业务规则及存储，新增类型、函数和成员写中文注释；避免依赖具体网页控件。
2. 在 `AppBridge` 添加 `Q_INVOKABLE` 方法，返回 `ServiceResult::success(data)` 或 `ServiceResult::failure(中文错误)`。只传递可序列化的业务字段及稳定 ID。
3. 在 `web/` 通过 `await desktopBridge.call("方法名", 参数)` 调用。桥接封装会把失败结果转换为异常；服务成功保存后发出变更信号，页面通过 `desktopBridge.on("信号名", 回调)` 刷新数据。
4. 新增网页文件时更新 `resources/app.qrc`，新增 C++ 文件时更新 `CMakeLists.txt`。补充涉及数据迁移、保存或系统交互的回归验证。

不要把任意文件路径执行、命令执行或任意外部页面访问直接暴露成网页接口。数据读写继续放在 Qt 服务中，页面资源继续随应用打包。


## 文件检索：NTFS 增量索引

文件检索页的“启用高速索引服务”会通过 Windows UAC 安装 `DesktopToolFileIndex` 服务。主窗口仍以普通用户权限运行。服务程序静态链接运行库，复制到受保护的 `%ProgramFiles%/DesktopToolIndex`；服务只接受本地的固定 NTFS 查询、枚举和日志读取操作，不接受文件路径、文件内容读取或任意写盘指令。没有服务时 NTFS 不会静默回退成全盘目录扫描。

首次使用读取 NTFS 主文件表，记录枚举前的 USN 断点，再从该断点补读变更。索引记录文件名、父目录标识和 MFT 序号；改名、移动更新记录关系，不重扫目录树。卷序列号、日志标识与断点有效时，重启加载缓存并补读停机期间日志；仅失效的卷重建。非 NTFS 卷仍使用扫描模式，重启重新扫描以弥补停机期间无法重放的通知。

索引和断点通过 `QSaveFile` 一起原子保存；有变化时每五分钟检查点保存，正常退出也保存。旧缓存版本会重建，不更改便签、截图等业务数据。服务空闲时等待请求，不维护第二份索引或扫描磁盘。后台日志读取每两秒触发，有单次时间预算；不存在持续忙循环。

查询使用三字符指纹预筛、预编译匹配器与 ASCII 快速路径，Unicode 内容仍做精确匹配；指纹复用记录的填充空间。相同查询分页复用结果，索引改变后缓存失效，新输入取消旧查询。搜索列表不再同步逐条读取磁盘大小和修改时间。结果仍按路径排序，展示上限为 8000 条，命中总数不受此限制；前端分页只追加新行。

手动性能基准：`out/build/web-x64-release/bin/FileSearchBenchmark.exe 3500000`。它构造相同的 350 万条文件名，输出首次搜索、第二页和进程工作集，不访问用户文件。2026-10-08 本机 Release 单轮对比：组合查询 `texture 987` 约 886 → 63 ms；宽泛查询 `mesh` 约 897 → 645 ms；`ext:dat` 约 949 → 598 ms；相同查询翻页约 848–904 → 不足 1 ms。索引基准工作集约 618 → 619 MiB。以上是合成数据测量，不代表任意真实磁盘或端到端 UI 的保证；路径冗余移除带来的实际节省未计入该基准。

回归测试包含日志跨批次改名、删除与创建组合标记、MFT 槽位复用、损坏批次拒绝、Unicode 匹配一致性、分页缓存失效、旧查询取消、目录事件压力与管道中止。普通权限测试不安装服务；真实 SCM 安装和磁盘 USN 首次枚举需在授权环境验证。

卸载软件时，卸载脚本会请求授权移除服务；取消授权则停止卸载并保留程序。也可对发布目录中的 `DesktopToolIndexService.exe --uninstall` 使用管理员权限，单独移除服务，不删除用户数据。当前安装器遇到已安装服务只启动它；升级服务二进制时需先卸载服务，再从新版文件检索页启用。

## 独立资源工具与默认应用

图像浏览器与视频播放器分别编译为 `DesktopToolImageBrowser.exe` 和 `DesktopToolVideoPlayer.exe`。构建产物位于 `out/build/web-x64-release/bin/tools/`；完整部署后位于应用根目录的 `tools/`，自带原生 Qt 运行库，不依赖主程序进程或 WebEngine。直接双击 exe 会选择文件，也可传入一个文件路径。主程序中的资源浏览、截图预览、录屏回放和文件检索均启动对应独立工具，退出主程序后工具可以继续使用。工具保留同目录切换、缩放旋转和播放控制，并只读取数据目录中的界面语言设置；可使用 `--data-dir` 指定设置目录。

仅构建并部署两个工具到项目根目录（不会安装主程序）：

```powershell
cmake --build --preset x64-release --target DesktopToolImageBrowser DesktopToolVideoPlayer
cmake --install out/build/web-x64-release --config Release --prefix . --component MediaTools
```

安装到原运行目录时，保留 exe 旁现有的 `data/` 即可；主程序直接读取该目录，两个工具默认读取上级主程序目录的同一份设置，无需额外传入 `--data-dir`。默认目录的开机自启命令也只包含 exe 路径。

可在主程序未启动时执行 `tools/DesktopToolImageBrowser.exe --register-associations`，登记两个独立工具的打开方式并立即退出。此操作保留 Windows 当前默认选择；已有 DesktopTool ProgId 的打开命令直接更新为对应工具，不再经过主程序。

完整执行 `cmake --install` 或发布打包脚本会同时部署主程序和 `tools/`。移动或分发工具时请保留 `tools/` 中的 Qt DLL、插件和 `qt.conf`。

在资源浏览器中点击“选择文件类型并设置默认应用…”，勾选所需图片或视频格式，打开 Windows 默认应用设置并确认。返回软件后自动读取真实关联，也可点击“刷新状态”。取消勾选只排除本次设置，已有默认程序需要在 Windows 设置中更换。Windows 10 或较早 Windows 11 如果只打开默认应用首页，可按扩展名、“DesktopTool 图像浏览器”或“DesktopTool 视频浏览器”搜索。两个默认应用分别登记到对应的独立 exe，保留旧版 ProgId 以迁移已有默认关联。程序不再删除 UserChoice 或直接覆盖扩展名默认值。


## 画板与数位板模式

侧栏进入「画板」，点击「打开画板」可打开独立原生窗口；重复点击会激活当前作品。提供画笔、白色橡皮、连续区域填充、取色、直线、矩形、椭圆和文字，可设置颜色、粗细、形状填充以及显示缩放。文字工具先输入文字，再点击画布放置。画布尺寸与笔宽使用像素，不涉及世界长度单位。

普通模式下，按住鼠标左键或笔尖接触即可绘制。开启「数位板模式」后，左键或笔尖接触仅定位，必须同时按住额外控制键才落笔，默认空格，可选择 Shift、F、D、A。松键立即结束该笔画，再次按键从当前光标位置开始，不连接定位期间的轨迹。按键是按住生效，不是开关；只有画布获得焦点时有效，切换窗口或打开对话框会清除落笔状态。原生数位笔事件和将笔模拟为鼠标的驱动均走相同门控。

支持新建白色画布、打开 PNG/JPEG/BMP/WebP 图片、保存及另存为 PNG/JPEG/BMP、复制图片和清空。保存采用原子替换；新建、打开、关闭以及从托盘退出前都会确认未保存修改。Ctrl+S 保存，Ctrl+Z 撤销，Ctrl+Y 重做。撤销最多保留 40 次且受 128 MiB 历史预算约束。数位板模式与控制键保存在数据目录的 `paint.ini`。

本功能参考 Windows 画图的基础绘图工作流，当前不包含图层、选区裁剪、压感笔刷或 AI 生成。画作需手动保存为图片；无屏数位板的实际驱动兼容性需使用设备确认。

### 关卡布局矢量工具

主界面的“关卡布局”页展示已保存项目，可新建、导入和打开独立编辑窗口。也可直接运行应用目录中的 `DesktopToolLevelEditor.exe`，支持 `--data-dir <目录>` 和可选的 `.level.json` 文件路径；默认与同目录主程序共享 `data/level-layouts`。外部文件可通过主界面的“导入项目”复制进入列表。

- 左侧绘制点集、连续折线、多边形，点击添加任意数量节点；Enter、右键或双击完成，Backspace 回退节点，Esc 取消未完成绘制。
- 选择工具可移动对象、拖动红色节点；双击线段插入节点，选中节点后 Delete 删除节点，左侧“删除对象”移除整个对象。右侧可选择对象、输入节点坐标、改名、修改填充/轮廓颜色、点直径和线宽；Ctrl+D 复制，Ctrl+Z/Ctrl+Y 撤销重做。
- 中键平移、滚轮缩放，“查看全部”显示完整关卡。坐标、粗细、网格尺寸统一使用米，输入和标尺显示两位小数；标尺可切换米、厘米和千米。
- 上方开关控制常用角吸附、最小角倍数、标尺、全视口十字线和网格。夹角以当前顶点指向上一顶点的射线与新线段计算；首段以水平轴为基准，最小角倍数优先。网格每五格加粗、十格更粗，缩小时按十倍降采样显示。
- 预设作为绘图样式使用：选择绿化、家具、水域或建筑后逐点勾勒多边形；选择道路后逐点绘制连续折线，线粗细即道路宽度。Enter、右键或双击完成，Backspace 回退节点，Esc 取消。预设提供默认颜色、粗细与渲染方法，绿化带植物纹样，道路带虚线，家具带木板线；绘制中可调整颜色与粗细，完成后可继续编辑节点和导出预设语义。
- `.level.json` 保存每个对象的唯一标识、名称、类型、预设、全部节点、颜色、粗细和辅助设置。原子保存及跨进程编辑锁保护工程；未保存退出会提示。
- 导出 PNG/SVG 使用全部对象的范围，可设置输出宽度及图例；SVG 包含独立对象分组、名称、预设属性和米制项目元数据。勾选“使用预设语义作为 SVG 对象名称”可让外部工具识别道路、绿化等用途。导出不包含编辑节点、网格与辅助线。
